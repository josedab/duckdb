└─────────────────────────────────────────────────────────────────────────────┘

Application Code
      │
      ▼
    Allocator (pluggable interface)
      │
      ├──→ DefaultAllocator (malloc/free)
      │       For small, temporary allocations
      │
      └──→ BufferAllocator (routes through BufferManager)
              For large allocations that need:
              - Memory awareness
              - Eviction capability
              - Per-query limits
              │
              ▼
        BufferManager
        ├─ Maintains block handles
        ├─ Pins/unpins for eviction control
        ├─ LRU eviction queue
        ├─ Memory pressure feedback
        │
        ├─→ In-Memory Storage
        │   (hot data, pinned)
        │
        └─→ Temporary Files (disk)
            (cold data, evicted)


┌─────────────────────────────────────────────────────────────────────────────┐
│                         JOIN OPTIMIZATION                                  │
└─────────────────────────────────────────────────────────────────────────────┘

Input: TableA JOIN TableB

Physical Plan Decision Tree:
    │
    ├─ If tables small? ─→ Nested Loop Join
    │   (no build phase, simple iteration)
    │
    ├─ If data pre-sorted? ─→ Merge Join
    │   (O(n+m), minimal memory)
    │
    └─ Default ─→ Hash Join (primary)
        │
        ├─ BUILD phase (parallel):
        │   Each thread builds local hashtable
        │   on TableB's join columns
        │   │
        │   └─ Storage:
        │       [SERIALIZED ROW][NEXT PTR]
        │       [SERIALIZED ROW][NEXT PTR]  ← Chained data
        │       ...
        │       [PTR][PTR][PTR]...          ← Hash table (linear probe)
        │
        ├─ MERGE local hashtables
        │
        ├─ BUILD pointer table
        │   (allocate hash slots)
        │
        └─ PROBE phase (parallel):
            Scan TableA, look up in hash table
            Return matching pairs from TableB
